# 公開入口與商業化決策

版本：1.0（2026-11-04）　｜　狀態：**決策草案，尚未上線、尚未有任何使用者或收入**

## 0. 決策摘要

| 層級 | 內容 | 是否處理真實企業資料 | 本階段 |
|---|---|---|---|
| A. 公開網站 | 繁體中文說明、教學文章、4 個在瀏覽器內計算的小工具 | **否**：工具在使用者瀏覽器內計算，不傳送數字 | 開發靜態網站（PR #29），**不部署** |
| B. 公開 Demo | 以合成資料**預先產生**的靜態結果頁 | **否**：沒有伺服器程式、沒有上傳功能 | 開發（PR #30），**不部署** |
| C. 企業私有版 | 現有 Streamlit 完整系統 | 是，但**只在客戶本機或內網**執行 | 維持現狀，以導入服務提供 |
| D. 雲端訂閱版 | 需要登入、租戶隔離、稽核等功能 | 是 | **延期**，市場驗證後才評估 |

**最重要的界線**：現有 Streamlit 系統沒有登入、沒有企業隔離，**不得公開部署，也不得公開接受真實企業資料**。

## 1. 目標客群與需要解決的問題

- **客群**：台灣少量多樣的金屬加工、機械零組件、設備組裝、中小型 OEM／ODM。主要使用者是業務主管、報價人員、成本會計、廠長。
- **問題**：
  - 供應商漲價後，不知道哪些有效報價會跌破毛利。
  - 小量訂單沒有攤提開機與換線費。
  - 歷史報價散落各處，新人無依據。
  - 報價改版沒有紀錄。
  - 內部試算表被誤寄給客戶。

以上都是根據產品設計推論的問題，**尚未經真實訪談驗證**。

## 2. 台灣製造業詢價到報價流程（一般化描述，待訪談驗證）

| 步驟 | 常見做法 | 本工具可以協助的部分 |
|---|---|---|
| 1. 收到詢價（圖面、數量、交期） | Email、LINE、電話 | — |
| 2. 確認圖面版次與材質 | 業務、工程 | 歷史報價比對時檢查版次 |
| 3. 估算成本 | BOM、材料價、工時、委外、開機費 | 成本影響、批次成本、數量階梯 |
| 4. 參考過去報價 | 翻舊 Excel、問資深同事 | 歷史報價匯入與相似案件 |
| 5. 決定售價 | 主管核准 | 只提供安全底價（試算）與警示，**不決定售價** |
| 6. 產生報價單並寄出 | ERP 或 Excel 範本 | 只提供不含內部資料的「草稿」；不寄送 |
| 7. 改版與追蹤 | 手動 | 版本比較 |

## 4. 免費、導入服務、訂閱、廣告模式比較

| 模式 | 收入來源 | 優點 | 風險 | 決定 |
|---|---|---|---|---|
| 免費教學與計算器 | 無直接收入 | 建立信任與搜尋流量 | 需要持續產出有品質的內容 | **採用**，作為入口 |
| 合成資料 Demo | 無直接收入 | 讓客戶不交資料也能看懂產品 | 需要清楚標示資料是合成的 | **採用** |
| 導入與覆核服務 | 單次 NT$3,000～8,000（**待驗證的假設**） | 不需要雲端處理機密資料 | 人力時間有限 | **採用**，作為初期主要收入假設 |
| 雲端訂閱 | 月費 | 規模化 | 需要完整的安全基礎；目前沒有 | **延期** |
| AdSense 廣告 | 依流量與核准結果而定 | 低維護 | 收入不確定、需要隱私揭露；B2B 流量低 | 只作為**潛在輔助**，不列入收入預估 |

## 6. 公開網站與企業私有版的系統界線

- 公開網站與 Demo 放在 `web/`，是**純靜態檔案**，不含任何 Python 伺服器程式。
- 公開網站不呼叫 `core/` 的上傳流程；Demo 的內容在建置時以合成資料預先產生。
- 公開頁面沒有檔案上傳元件，沒有對外送出資料的表單，也沒有第三方分析工具。
- 試用申請：只提供聯絡方式的說明；**不在網站上蒐集**企業的 Excel 或報價資料。
- 企業私有版：只在客戶本機或內網以 Docker 或 Python 執行（見 `docs/DEPLOYMENT_CHECKLIST.md`）。

## 7. 企業資料安全與機密保護

- 真實企業資料只在客戶的環境中處理；服務方需要處理時，必須先取得書面授權並約定刪除期限（`docs/delivery/03`、`09`）。
- 公開網站計算器的數字只存在使用者瀏覽器的記憶體中，不寫入 cookie 或 localStorage，也不送出。
- 不在任何處理企業資料的頁面放置廣告或追蹤碼。

## 9. AdSense 政策與隱私揭露要求（上線前需依 Google 最新官方政策查證）

- 需要有足夠的原創內容；網站需由站長申請並等待審核，**不保證核准**。
- 需要隱私權政策，揭露第三方（包含 Google）可能使用 cookie 來放送廣告，並說明使用者如何管理。
- 若有歐洲經濟區、英國或瑞士的使用者，可能需要符合 Google 的使用者同意政策（例如使用經認證的同意管理平台）。
- 不得自行點擊、鼓勵點擊或製造虛假流量。
- 不在計算器頁、Demo 頁或任何可能處理企業資料的頁面放置廣告。
- 在隱私權政策完成、使用者決定申請之前，**網站不放任何廣告程式碼**。

## 10. 不適合公開部署的現有功能

- `app.py` 及 `pages/` 下所有頁面：都可以上傳 Excel，而且沒有登入與隔離。
- 欄位對應頁：會讀取完整的企業匯出檔。
- 歷史報價與報價工作台：包含其他客戶的價格與成本。
- Docker 映像：預設只綁定 127.0.0.1；**不可**改成公開連接埠。

## 11. 未來安全 SaaS 的最低技術條件（延期）

- 帳號、登入、多因素驗證、角色權限。
- 每家企業的資料在儲存與運算層面都完全隔離；不同企業之間無法查詢彼此資料。
- 傳輸與儲存加密；金鑰管理。
- 上傳檔與結果的保存期限、刪除流程、刪除證明。
- 稽核紀錄、異常監控、備份與還原演練。
- 第三方安全測試；個資與營業秘密相關法律審閱。
- 服務條款、隱私政策、資料處理協議（需專業人士審閱）。

## 12. 上線 Go／No-Go 門檻

| 項目 | 公開靜態網站 | 雲端訂閱版 |
|---|---|---|
| 網站內容與計算器測試全部通過 | 必要 | 必要 |
| 沒有上傳元件、沒有第三方追蹤（以測試確認） | 必要 | — |
| 隱私權政策與服務條款草案經使用者確認（廣告前需經專業審閱） | 必要 | 必要 |
| 使用者決定網域、託管平台並授權部署 | 必要 | 必要 |
| 至少 10 份真實訪談、3 家試算 | 不必要 | **必要** |
| 第 11 節的技術條件全部完成，並通過第三方測試 | 不適用 | **必要** |

目前狀態：公開靜態網站在使用者授權部署之前為 **No-Go**；雲端訂閱版為 **No-Go**。

## 13. 設計審查（四個視角）

| 視角 | 質疑 | 決定 | 理由與界線 |
|---|---|---|---|
| 台灣製造業報價主管 | 公開網站上的計算器結果會被當成正式報價 | **採納** | 每個工具都標示「試算，不是報價」，並提供計算式 |
| 台灣製造業報價主管 | 希望直接上傳 ERP 檔看結果 | **駁回** | 公開入口不處理真實資料；改用 Demo 與本機私有版 |
| 台灣製造業報價主管 | 文章太多會看不完 | **採納** | 只寫 6 篇有實際步驟的教學，不大量產生文章 |
| SaaS 產品經理 | 應該直接做雲端訂閱版，才能規模化 | **延期** | 安全基礎與市場驗證都還沒完成（第 11、12 節） |
| SaaS 產品經理 | 沒有註冊就無法追蹤轉換 | **駁回** | 不蒐集個資；以真人訪談與試用作為驗證指標 |
| SaaS 產品經理 | Demo 用現有 Streamlit 隱藏上傳按鈕就好 | **駁回** | 隱藏按鈕不能防止直接呼叫上傳功能；Demo 改為預先產生的靜態頁 |
| 資安與資料保護工程師 | 計算器輸入可能被分析工具收集 | **採納** | 不放任何第三方程式；測試確認頁面沒有外部 script 與網路請求程式碼 |
| 資安與資料保護工程師 | 試用申請表單可能收到機密檔案 | **採納** | 不提供上傳或送出表單，只說明聯絡方式，並提醒不要寄送機密檔案 |
| 資安與資料保護工程師 | 靜態網站也可能被植入外部資源 | **採納** | 測試會檢查所有頁面只引用站內資源 |
| 廣告與 B2B 商業化負責人 | 先放 AdSense 測試收益 | **延期** | 需要隱私權政策與足量內容，並由使用者自行申請；目前不放程式碼 |
| 廣告與 B2B 商業化負責人 | B2B 流量低，廣告收入可能很少 | **採納** | 廣告不列入收入預估；主要收入假設為導入服務 |
| 廣告與 B2B 商業化負責人 | 在計算器旁放廣告最有曝光 | **駁回** | 不在工具頁、Demo 頁放廣告，避免誤導與資料疑慮 |
