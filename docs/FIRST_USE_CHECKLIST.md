# 首次使用驗收清單（企業自行勾選）

對象：第一次在公司電腦上安裝與使用本系統的業務、成本會計、採購或工廠主管。
全部使用 `samples/` 的**合成資料**；驗收過程中**不要**放入真實客戶資料。
預估時間：約 60 分鐘。每完成一項就打勾，並記下日期與操作人（人工填寫）。

> 重要：本系統的自動測試已在 GitHub 提供的 Windows／macOS／Linux 雲端測試機（runner）上通過。
> 但這**不代表**已在貴公司的**實體電腦**上驗證；公司防毒、權限政策、中文帳號名稱、雲端同步資料夾都可能造成差異。
> 所以請在實際要使用的那台電腦上，親自完成這份清單。

## 1. 安裝成功
- [ ] 依 `docs/LOCAL_DEPLOYMENT.md` 第 2 節（Windows）或第 3 節（macOS）完成安裝，沒有修改任何系統安全設定。
- [ ] 執行 `tools/check_env.py --data-dir <打算放資料的資料夾>`，四項都顯示 `[OK]`（Python 3.11、套件與 `requirements-lock.txt` 相同、連接埠、資料夾可寫入）。
- [ ] （選做，只適用於從原始碼專案安裝；交付包不含測試）`python -m pytest -q -rs` 顯示 0 failed、0 skipped。

## 2. 系統正常啟動
- [ ] 雙擊 `start_windows.bat`（Windows）或 `start_macos.command`（macOS），瀏覽器開啟視窗中顯示的 `Local URL`，看到「毛利風險報告」頁面。
- [ ] 關閉啟動視窗後，再雙擊一次，可以**再次啟動**。
- [ ] 若看到網址是 8502 而不是 8501：表示 8501 被占用（通常是前一個視窗沒關）。這不是錯誤，請以顯示的網址為準。

## 3. 只有本機可以連線
- [ ] 在同一台電腦開 `http://127.0.0.1:8501` 可以使用。
- [ ] 用**另一台**電腦或手機開 `http://<這台電腦的 IP>:8501` **連不上**（預設只監聽 127.0.0.1）。
- [ ] 防火牆或 macOS 詢問是否允許連入時，選了「取消／拒絕」。

## 4. 流程 A：供應商調價 → 成本影響（Excel 可以匯入、財務計算符合範例）
1. 主頁先選報告類型「客戶報價風險報告」。
2. 上傳 `samples/sample_bom.xlsx`、`samples/sample_price_increase.xlsx`、`samples/sample_open_quotes.xlsx`。
3. 試算基準日 2026-12-01、最低毛利率 15%，按「產生客戶報價風險報告」。
- [ ] 三份 Excel 都能匯入，沒有錯誤。
- [ ] 摘要：總成品數 6、可完整試算 6、預估每月總成本增加 **61,597.00**、需人工覆核 **3** 筆。
- [ ] 報告可下載：按「下載可稽核 Excel 報告」取得 `result.xlsx`，可用 Excel 開啟。
- [ ] 下載的 `result.xlsx` 有 6 張工作表（Summary、Cost Impact、Exceptions、Line Audit、Quote Risk、Quote Exceptions），Line Audit 有 40 列。
- [ ] 例外不會被略過：有問題的資料會出現在 Exceptions／Quote Exceptions，並寫明工作表、Excel 列號與原因。

## 5. 流程 B：歷史報價 → 安全底價 → 版本比較 → 客戶草稿
1. 左側選單「歷史報價與建議報價」：上傳 `samples/historical/` 兩份歷史報價檔與兩份 `mapping_*.json`（欄位對應），各自選擇對應設定後按「匯入歷史報價」。
2. 「② 目前成本」上傳 `sample_bom.xlsx` 與 `sample_price_increase.xlsx`；查詢 P-1001、60 件、圖面版次 B、試算日 2026-12-15，勾選調價生效日。
3. 按「產生建議報價」。
- [ ] 覆核狀態為「歷史價格低於安全底線」，安全底價 **1,026.12**，並列出相似的歷史案件。
- [ ] 下載的建議報價報告標示「僅供內部試算，需人工核准」。
4. 左側選單「報價工作台」：選「明細批次成本」→「手動輸入」，填入成品 P-DEMO、材料 100、人工 40、製費 30、委外 10、開機 1000、換線 500、其他 0，勾選確認；數量 10, 100, 500、目標毛利率 20%，按「計算數量階梯」。
- [ ] 安全底價（試算）：10 件 **412.50**、100 件 **243.75**、500 件 **228.75**。
- [ ] 可以上傳兩個報價版本進行比較，並看到差異說明。
- [ ] **客戶草稿**標示「未核准草稿」（價格經人工確認後才改為「報價草稿」），而且**不含成本、毛利、安全底價或其他客戶的歷史價格**。

## 6. 流程 C：案件管理 → 實際成本 → 備份與還原
1. 左側選單「案件工作台」：勾選「啟用本機保存」，輸入**測試用**資料庫路徑（例如 `文件\報價資料\test_cases.db`）。
2. 上傳 `samples/rfq/rfq_sample.xlsx`，填寫原因，按「保存詢價案件」。
3. 選擇 `C-001|RFQ-2612-001|v1`：狀態改為「待人工覆核」；新增報價版本（單價 300、數量 100、預估單位成本 200）；回填「成交」、數量 100、實際總成本 22500。
- [ ] 畫面依序出現「尚未保存」→「已保存」；報價版本後出現「報價未核准」提醒。
- [ ] 同樣的內容再按一次「新增報價版本」，顯示「與剛才保存的內容相同，未重複保存」，不會多出一個版本。
- [ ] 差異表：預估毛利率 **33.33%**、實際 **25.00%**、成本差異 2,500、毛利率下降 8.33 個百分點。
- [ ] 「內部稽核報告」與「客戶報價草稿」是兩個不同的下載按鈕；客戶草稿中沒有「成本」、「毛利」或 22500。
4. **備份**：輸入備份檔路徑，按「建立備份」，看到「已建立備份」。
5. **修改**：再新增一個報價版本（例如單價 999），讓資料與備份不同。
6. **還原**：輸入剛才的備份檔路徑，確認檢查結果為「完整」；不勾選確認時按「還原」應被拒絕；勾選後再按。
- [ ] 還原成功，案件回到備份時的內容（單價 999 的版本消失），稽核紀錄完整，並另外留下一份 `before_restore` 檔。

## 7. 資料庫位置受到保護
- [ ] 正式資料庫放在**本機**資料夾（不是網路磁碟，也不是 OneDrive、Dropbox、iCloud 同步資料夾），也不在程式資料夾內。
- [ ] 該資料夾只有使用者本人的帳號能讀寫；磁碟已啟用 BitLocker（Windows）或 FileVault（macOS）。SQLite 檔案本身**沒有加密**。
- [ ] 驗收完成後，刪除測試資料庫與測試備份，再建立正式資料庫。

## 8. 更新軟體前保護資料
- [ ] 已閱讀 `docs/LOCAL_DEPLOYMENT.md` 第 10 節：先建立「更新前」備份並確認完整，保留舊版資料夾，再安裝新版。

## 看到阻擋或錯誤時
- 畫面上的錯誤都會寫出原因；Excel 資料問題會寫出工作表與 Excel 列號，修正原始檔後重新上傳即可。
- 安裝、資料庫、備份、權限、連接埠等問題，請看 `docs/LOCAL_DEPLOYMENT.md` 第 11 節對照表。
- 本系統沒有登入與權限，只供**單一使用者、單一電腦**使用；不支援多人同時使用。
