# 60 秒產品展示腳本

> 全程使用 `samples/` 的**合成資料**（虛構公司、虛構客戶、虛構金額）。
> 不要用真實客戶的檔案做展示，也不要把服務部署在公開主機上展示。

## 準備（展示前 5 分鐘）

1. 在自己的電腦執行 `streamlit run app.py --server.address=127.0.0.1`，或使用 `docker compose up --build`。
2. 開啟 `http://127.0.0.1:8501`。
3. 準備好三份檔案：
   - `samples/sample_bom.xlsx`
   - `samples/sample_price_increase.xlsx`
   - `samples/sample_open_quotes.xlsx`
4. 備用：如果現場無法操作，直接打開 `demo/example_result.xlsx`，或播放 `docs/media/demo_walkthrough.webm`。

## 腳本

| 秒數 | 畫面 | 要說的話 |
|---|---|---|
| 0–10 | 首頁 | 「供應商剛通知漲價。我們想知道：**已經報給客戶、還有效的報價**，哪幾張會跌破公司的毛利底線？」 |
| 10–20 | 上傳三份 Excel | 「從 ERP 匯出三份 Excel：BOM、供應商漲價清單、客戶報價。試算日選 12 月 1 日，毛利底線 15%。」 |
| 20–35 | 摘要 | 「8 張報價裡，有 3 張跌破 15%。依報價數量推估，這 3 張的情境成本增加是 3,266 元。這是推估金額，不是已經確定的損失。」 |
| 35–50 | 需人工覆核清單 | 「最危險的是第 1 列：P-1003，原本毛利就只有 14.2%，漲價後剩 11.6%；要回到 15%，單價至少要 665.89。每一列都寫清楚原因。」 |
| 50–60 | 下載 | 「下載的 Excel 可以逐列追溯到原始 BOM 和報價。系統不會改 ERP，也不會寄信給客戶，最後由您決定。」 |

## 加演：歷史報價記憶庫（約 40 秒，合成資料）

| 秒數 | 畫面 | 要說的話 |
|---|---|---|
| 0–10 | 匯入兩份格式不同的歷史報價 | 「業務部和舊系統的報價檔格式不同，各自對應一次就能合併；重複的那筆會自動去掉。」 |
| 10–25 | 查詢 P-1001、60 件、版次 B | 「11 筆舊報價裡只有 3 筆真的能比，其他每筆都寫了原因：舊版圖面、含稅、外幣、數量差太多。」 |
| 25–40 | 覆核狀態 | 「以目前成本，毛利 15% 至少要報 1,026.12，但以前曾報過 990；12 月漲價後還報同樣的 1,050。系統只提醒，價格由主管決定。」 |

不要說「AI 算出最佳價格」或「保證成交」。

## 常見追問與回答

- **能直接讀我們 ERP 的檔案嗎？**
  先用「Excel 欄位對應」頁逐欄對應。我們沒有宣稱支援任何 ERP 的原生格式，要用您的去識別化樣本實際試過才知道。
- **資料會上傳到雲端嗎？**
  本工具在您的電腦或公司內網執行。展示時用的是合成資料。
- **算出來的價格可以直接報給客戶嗎？**
  不建議。它只是成本與毛利底線的計算結果，要由業務主管判斷。

## 展示時不要說

- 「已經有很多客戶在用」（目前沒有任何客戶紀錄）
- 「保證能幫您把價差拿回來」
- 「支援鼎新、SAP……」（只能說「可以用欄位對應試試看」）
- 「市場上沒有類似工具」
