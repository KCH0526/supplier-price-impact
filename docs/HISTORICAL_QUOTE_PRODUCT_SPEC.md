# 歷史報價記憶庫與建議報價模組 規格

英文名稱：Quote Memory & Pricing Advisor
版本：1.0（2026-11-04）　｜　適用 PR：#16～#20　｜　狀態：技術開發中，只用合成資料驗證

本模組延伸既有的「供應商漲價與客戶報價毛利風險覆核器」。既有規格 `docs/IMPLEMENTATION_SPEC.md` 不變。

## 1. 使用者與使用情境

| 使用者 | 情境 |
|---|---|
| 業務／估價人員 | 客戶詢價 P-1001、200 件，想知道以前類似條件報過多少、目前成本下最低能報多少 |
| 報價主管 | 核准報價前，檢查有沒有低於毛利底線、有沒有沿用材料漲價前的舊價格 |
| 新進業務 | 資深估價員不在時，找得到過去的報價依據與來源檔案 |
| 成本會計 | 確認建議所用的成本是完整成本，而不是只有材料 |

典型流程：匯入多份歷史報價 Excel → 查詢成品與數量 → 看可比較的歷史證據 → 看目前成本安全底線 → 輸出**需人工核准**的覆核報告。

## 2. 功能界線

| 已有功能（不改動行為） | 新增功能 |
|---|---|
| BOM／供應商調價配對、完整成本、毛利率、最低售價（`core/matcher.py`、`calculator.py`、`quote_risk.py`） | 歷史報價匯入與標準化（PR #16） |
| 客戶未結報價毛利風險（OpenQuotes） | 可解釋的相似案件檢索（PR #17） |
| Excel 欄位對應頁 | 成本底線＋歷史參考的報價覆核建議（PR #18） |
| 報告匯出、公式注入防護、上傳限制 | 「歷史報價與建議報價」頁面與覆核報告（PR #19） |

新模組只**讀取**既有模組的結果，不改變既有計算。

## 3. 歷史報價資料欄位（工作表 `HistoricalQuotes`）

### 必要欄位（必須對應到來源欄位；值的規則見下）

| 欄位 | 規則 |
|---|---|
| 報價單號 | 文字；保留前導零；不可空白 |
| 報價行號 | 文字；保留前導零；不可空白 |
| 報價日期 | Excel 日期或 `YYYY-MM-DD`；不可空白 |
| 客戶代碼 | 文字；保留前導零；不可空白 |
| 成品編號 | 文字；保留前導零；不可空白 |
| 報價數量 | 大於 0 的有限數字；不可空白（空白不視為 0） |
| 計價單位 | 例如 pcs、set；不可空白；不做任何單位換算 |
| 幣別 | 不可空白；只有 `TWD` 可直接比較，不推測匯率 |
| 報價單價 | 大於 0 的有限數字；每 1 計價單位 |
| 稅別 | 「未稅」或「含稅」。空白或其他文字＝**不明**。只有「未稅」可直接比較，不自動換算 5% 營業稅 |

### 選填欄位（沒有就留空，系統不會補值）

報價版本、成品名稱、規格圖面版次、材質、製程類別、報價狀態、成交狀態、交期、備註。

- **成交狀態**只接受「成交」、「未成交」、「未知」；空白或其他文字一律視為**未知**，絕不解讀為成交。
- **報價狀態**原樣保留，不參與計算。

### 系統加上的欄位

| 欄位 | 意義 |
|---|---|
| 來源檔案、來源工作表、來源Excel列號 | 追溯來源。重新匯入標準化檔時，保留第一次匯入時的原始來源 |
| 可直接比較 | 列有效、幣別為 TWD、稅別為未稅，才會是「是」 |
| 無法比較原因 | 例如「稅別不明」「幣別 USD，不換匯」 |
| 最新版本 | 同一報價單號＋行號的多個版本中，依報價日期判斷最新；日期相同而版本不同時無法判斷，標為空白並警告 |
| 成交狀態（正規化） | 成交／未成交／未知 |

## 4. 匯入規則（PR #16）

- **識別鍵**：報價單號＋報價行號＋報價版本（版本空白也視為一個值）。
- **核心欄位**：報價日期、客戶代碼、成品編號、報價數量、計價單位、幣別、報價單價、稅別、規格圖面版次；
  再加上雙方都明確填寫（不是「未知」）的成交狀態。
- **重複匯入**：識別鍵相同、核心欄位也完全相同 → 只保留第一筆，並記錄為提醒，不是錯誤。
  同一筆報價從不同系統匯出時，備註、品名等描述欄位可能不同；這種情況不算衝突，以第一筆為準。
- **衝突**：識別鍵相同但核心欄位不同 → 該識別鍵的**所有列都阻擋**，因為無法判斷哪一筆正確。
- **修訂版本**：單號＋行號相同、版本不同，屬於合法資料，全部保留。
- **公式**：以 `data_only` 讀取，不執行公式。沒有快取值的公式儲存格會成為空白。
- **上限**：
  - 單檔 20 MB，每工作表 50,000 列（沿用既有上限）。
  - 一次最多 20 個檔案，累計 100 MB，累計 100,000 列。
- **儲存**：上傳內容只在記憶體中處理。只有使用者主動下載的標準化 Excel 會離開記憶體。
- **欄位對應**：每個來源檔可以有自己的欄位對應，沿用 `core/field_mapper.py` 的規則：明確指定、不猜測、同一來源欄位不可對應到兩個欄位。已經是標準欄位名稱的檔案（例如之前下載的標準化檔）可以直接匯入。

## 5. 相似案件比對規則（PR #17）

輸入：成品編號（必填）、比較數量（必填）、試算日（必填）、計價單位（必填）、圖面版次（選填）、客戶代碼（選填，只用來標示是否同客戶）。

只使用「可直接比較」且為「最新版本」的列。每一筆都要記錄**選入或排除**，以及原因。

| 條件 | 規則 | 不符時 |
|---|---|---|
| 成品編號 | 必須完全相同（不做名稱相似比對） | 不列入 |
| 計價單位 | 必須完全相同 | 排除：單位不同 |
| 幣別、稅別 | TWD、未稅 | 排除：不可直接比較 |
| 圖面版次 | 指定時必須相同；任一方空白 → 列入，但標示「版次未知」 | 排除：版次不同（舊版圖面風險） |
| 數量 | 歷史數量在比較數量的 0.5～2 倍之間 | 排除：數量級距不同 |
| 報價日期 | 在試算日之前 730 天內（含當天）；晚於試算日的不使用 | 排除：過舊或晚於試算日 |
| 客戶 | 不影響是否列入，只標示同客戶或其他客戶 | — |

**可比較性等級**：
- **A**：所有條件都符合，且圖面版次相同。
- **B**：所有條件都符合，但版次未知。

**統計門檻**：A＋B 合計至少 **3 筆**，才計算參考統計（筆數、最低、中位數、最高、最近一筆）。少於 3 筆時一律顯示「**歷史資料不足**」，不顯示區間。

歷史報價不是成交價。成交筆數另外列出；成交狀態未知的報價不算成交。

## 6. 建議報價規則（PR #18）

**A. 成本安全底線**
- 只有既有計算結果為「可完整試算」且為完整成本口徑時才計算：
  安全底價 = 新完整單件成本 ÷（1 − 目標毛利率），以 Decimal **無條件進位**到小數兩位。
- 成本不完整、缺少人工製費、有阻擋例外 → 不輸出底價，說明缺少什麼。

**B. 歷史市場參考**：使用第 5 節的統計；資料不足時不輸出。

**C. 人工覆核建議**（只是狀態與原因，不是自動售價）

| 狀態 | 條件 |
|---|---|
| 無法提供安全底價 | A 無法計算 |
| 歷史資料不足 | A 可算，但 B 不足 3 筆 |
| 歷史價格低於安全底線 | 參考區間的最低價低於安全底價：不得直接沿用舊價 |
| 可參考歷史區間 | 參考區間的最低價不低於安全底價 |

**異常警示**
- 歷史價格低於底線。
- 同條件價格差異過大：（最高 − 最低）÷ 中位數 > 30%。
- 最近一筆可比較報價的版次和指定版次不同或未知：舊版價格風險。
- 材料漲價後仍沿用舊價：有供應商調價生效日時，生效日之後的可比較報價單價和生效日之前最近一筆相同。
- 價格單位不一致：同成品有其他計價單位的歷史報價，已排除並提醒。
- 歷史資料品質不足。
- 缺少目前完整成本。

**不做**：自動發送、自動承諾售價、自動折扣、推估成交率、把未知當成交。

## 7. 報告與資料隔離（PR #19、#20）

覆核報告的工作表：Summary、Quote Recommendation、Historical Evidence、Price Exceptions、Data Quality。

- 所有文字都經過公式注入防護。
- 每個工作表都標示「僅供內部試算，需人工核准」。
- **Historical Evidence 含其他客戶的價格，屬於內部資料**，不可轉交給客戶。
- 若輸出「對外報價草稿」，只能包含成品、數量、單位、幣別，以及經人工填寫的價格欄位，**不含**任何歷史價格或其他客戶代碼。

## 8. 資安要求

- 不呼叫外部 API、不使用外部 AI 或模型、沒有資料庫、沒有永久儲存。
- 沿用既有的上傳大小、解壓縮與資料列上限，另加累計上限。
- 讀取時不執行公式；匯出時所有文字都做公式注入防護。
- 只在本機或私有內網 Docker 執行；不公開部署含真實資料的服務。

## 9. 驗收標準

- PR #16：本規格第 4 節的 15 種情況都有測試。
- PR #17：可比較性條件逐項有測試，包括「資料不足時不輸出區間」。
- PR #18：安全底價、狀態、異常的測試預期值都是手算的字面值，不由被測函式產生。
- PR #19：瀏覽器實測匯入、查詢、建議、下載報告。
- PR #20：完整回歸、對抗測試，以及第 7 節的資料隔離檢查。

## 10. 已知限制

- 只做「成品編號完全相同」的比對；不做圖面、材質或製程的相似度推估。
- 不支援匯率、含稅換算、單位換算。
- 0.5～2 倍數量級距、730 天、3 筆門檻、30% 差異都是**預設規則**，尚未經真實客戶驗證；應在導入時與客戶確認。
- 歷史報價不等於成交價，也不代表市場願付價格。

## 11. 設計審查（四個視角）

### 11.1 台灣中小製造商的報價主管

| # | 原始主張 | 質疑 | 決定 | 最終界線 |
|---|---|---|---|---|
| 1 | 系統直接給一個「建議售價」 | 單一數字會被業務直接照抄，出事責任不清；也不知道系統依據什麼 | **駁回** | 只給安全底價、歷史區間與狀態原因，售價由人決定 |
| 2 | 用成品名稱相似度找類似件 | 名稱相似不代表製程相同，例如「法蘭」的尺寸、材質差很多 | **駁回** | 只比對成品編號完全相同；材質、製程只作為顯示與篩選 |
| 3 | 數量差太多也該列入 | 100 件與 5,000 件的單價結構完全不同 | **採納（有限度）** | 0.5～2 倍級距，超出就排除並寫明原因；導入時再與客戶確認 |
| 4 | 也要顯示未成交報價 | 未成交價可能偏高，混在一起會誤導 | **採納** | 全部列出，並標示成交狀態；成交筆數另外統計，未知不算成交 |

### 11.2 ERP 與成本會計顧問

| # | 原始主張 | 質疑 | 決定 | 最終界線 |
|---|---|---|---|---|
| 1 | 含稅價自動除以 1.05 | 有些報價含運費、模具費，或稅率不同；自動換算會失真 | **駁回** | 只用未稅價；含稅或不明時標示不可直接比較 |
| 2 | 修訂版本只保留最後一版 | 舊版也是證據；而且「最後」不一定能判斷 | **採納（修正）** | 全部保留；依報價日期判斷最新版，日期相同時不猜測，提出警告 |
| 3 | 成本不完整時先用材料成本算底價 | 會低估底價，讓業務以為安全 | **採納** | 成本不完整時不輸出底價，並列出缺少的項目 |
| 4 | 自動合併不同幣別 | 匯率日與匯率來源都不明 | **駁回** | 非 TWD 一律不可直接比較 |

### 11.3 資安與資料隱私審查者

| # | 原始主張 | 質疑 | 決定 | 最終界線 |
|---|---|---|---|---|
| 1 | 匯入後永久保存成記憶庫 | 會累積大量客戶價格，外洩衝擊大，也違反目前不持久化的設計 | **延期** | 不永久保存；使用者自行下載標準化檔，下次重新匯入 |
| 2 | 報告直接給客戶看 | 歷史證據含其他客戶的價格，屬於營業秘密 | **駁回** | 內部證據與對外草稿分開；對外草稿不含任何歷史價格或其他客戶代碼 |
| 3 | 用外部 AI 找相似件 | 會把報價資料送出公司 | **駁回** | 只用本機、可解釋的規則 |
| 4 | 不限制上傳數量 | 可能耗盡伺服器記憶體 | **採納** | 單檔、累計檔數、累計大小、累計列數都設上限 |

### 11.4 負責銷售與導入服務的人

| # | 原始主張 | 質疑 | 決定 | 最終界線 |
|---|---|---|---|---|
| 1 | 宣傳「AI 智慧報價」 | 沒有模型、也沒有學習，這樣說是誤導 | **駁回** | 說法改為「可追溯的歷史報價參考＋成本底線檢查」 |
| 2 | 宣稱可縮短報價時間 50% | 沒有任何實測 | **駁回** | 只描述功能；節省時間需要客戶實測後才能說 |
| 3 | 一開始就支援所有 ERP 格式 | 不可能驗證 | **延期** | 用欄位對應處理，每家客戶個別確認 |
| 4 | 門檻寫死 | 各公司習慣不同 | **延期** | MVP 使用固定預設值並寫入報告；是否開放調整，依真實客戶回饋決定 |

### 11.5 未解決的疑義

沒有會影響計算正確性的阻擋級疑義。第 10 節的預設門檻值需在第一次客戶導入時確認。
