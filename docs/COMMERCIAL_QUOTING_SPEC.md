## 2. 客戶報價草稿（PR #21）

- 以**允許欄位清單**組成草稿。程式只會複製清單內的欄位，不是從內部報告刪除欄位。
- **表頭可含**：客戶代碼、客戶名稱、報價單號、報價版本、報價日期、報價有效期限、交易條件（人工填寫）。
- **明細可含**：成品編號、成品名稱、規格圖面版次、數量、計價單位、幣別、報價單價（人工填寫）、合計金額、交期。
- **不得含**：其他客戶代碼或報價、歷史證據、成本、底價、毛利率、供應商成本、風險分數、內部備註。
- 草稿模組**不接受**任何內部建議或成本物件，所以不可能自動帶入價格。
- **價格**：
  - 空白 → 合計留空，整份草稿標示「**未核准草稿**」。
  - 0、負數、非數字 → 阻擋。
- **合計**：數量 × 單價，以 Decimal 計算，四捨五入到小數兩位（顯示用金額）。
- **標示**：
  - 價格全部填寫，且使用者勾選「價格已由權責人員確認」時，標示「**報價草稿（價格已人工填寫，本系統不提供核准或簽名）**」。
  - 其他情況一律標示「**未核准草稿**」。
- **檔案內容**：
  - 只有一張工作表「報價草稿」，沒有隱藏工作表、沒有公式、沒有定義名稱。
  - 所有文字都經過公式注入防護。
  - 一份草稿只有一位客戶、一種幣別。
- 系統不寄送、不簽名、不產生核准紀錄。

## 3. 批次成本模型（PR #22）

**兩種模式互斥。** 每個成品只能用其中一種，由使用者明確選擇，系統不自動切換。

| 模式 | 成本來源 | 批次固定費 |
|---|---|---|
| **A. 既有完整單件成本** | 既有計算結果中「可完整試算、完整成本口徑」的新成本 | **不加算**。既有 ProductCost 可能已包含批次相關費用，無法證明沒有包含時不得加算，以免重複計算 |
| **B. 明細批次成本** | 使用者提供的 `BatchCost` 資料 | 依明細加算 |

**模式 B 的欄位**（工作表 `BatchCost`）

| 欄位 | 必要 | 口徑 |
|---|---|---|
| 成品編號 | 是 | 文字 |
| 規格圖面版次 | 否 | 文字 |
| 成本基準日 | 是 | 不可晚於試算日；早於試算日 365 天以上提出警告 |
| 幣別 | 是 | 只接受 TWD |
| 單位 | 是 | 只接受 pcs |
| 單件材料變動成本、單件人工變動成本、單件製造費用、單件委外加工費 | 是 | 每 1 pcs、TWD、≥ 0 |
| 每批開機設定費、每批換線治具費、其他批次固定費 | 是 | 每批、TWD、≥ 0 |
| 成本來源 | 是 | 文字，例如「112 年標準成本表」 |
| 成本完整性狀態 | 是 | 只有「已確認」可以計算 |

- **0 與空白不同**：0 是明確確認的值；空白代表未知 → 阻擋，絕不當作 0。
- 同一成品＋版次在同一份資料中出現兩筆以上 → 阻擋，不任選其一。
- 不從既有成本推測材料、人工、製費的比例；不使用舊報價當成本。

## 4. 數量階梯（PR #23）

```text
每件情境成本 = 單件變動成本 + 批次固定成本 ÷ 數量
安全底價     = 每件情境成本 ÷ (1 − 目標毛利率)，Decimal 無條件進位到小數兩位
```

- 模式 A 的批次固定成本為「未計入」，每件情境成本就等於既有完整成本，並在每一列註明。
- **數量**：必須是正整數（pcs），不可重複，一次最多 20 個。
- **最低訂購量（MOQ）**：有提供時，低於 MOQ 的數量標示「低於最低訂購量」，不提供底價。
- **毛利率**：0 ≤ 目標毛利率 < 1。
- **歷史差異**：只在歷史參考達到 3 筆門檻時，才顯示「安全底價 − 歷史中位數」。
- **不模擬**：原料議價、良率、工時、委外階梯價隨數量的變化。資料不足時不猜測，並在報告中寫明。
- 名稱一律稱為「**安全底價（試算）**」，不使用「最佳價格」「建議售價」。

**驗收案例**（單件變動 180、每批固定 1,500、毛利率 20%）

| 數量 | 每件成本 | 安全底價 |
|---:|---:|---:|
| 10 | 330 | 412.50 |
| 100 | 195 | 243.75 |
| 500 | 183 | 228.75 |

## 5. 報價版本比較（PR #24）

- **輸入**：歷史報價資料、報價單號、行號、兩個版本，以及選填的人工變更原因。
- **版本先後**：
  - 依報價日期判斷。
  - 同一天時，除非使用者明確確認哪一版較新，否則標示「版本先後無法判定」，只列出兩邊的值，不計算方向。
  - 系統不依版本號的文字猜測先後。
- **比較欄位**：報價日期、報價版本、客戶、成品、圖面版次、數量、計價單位、幣別、稅別、單價、未稅金額、交期、成交狀態。
- **單價差額**：只有幣別、計價單位、稅別（未稅）、數量**全部相同**時才計算；否則寫明無法直接比較的原因。
- **未稅金額**（數量 × 單價）差額：只有幣別相同且都是未稅時才計算。
- **輸出**：每個欄位的舊值、新值、差額、差異百分比、說明、雙方的來源檔案與列號。
- **變更原因**：只顯示人工輸入的內容，系統不推測。

## 6. 報價工作台與報告（PR #25）

頁面清楚區分四個概念：

| 概念 | 意義 |
|---|---|
| 歷史參考價格 | 過去的報價，不是成交價 |
| 目前完整成本 | 既有成本或批次成本的計算結果 |
| 安全底價（試算） | 依成本與毛利率算出的下限 |
| 人工決定的正式售價 | 只有人填寫；系統不填 |

- **內部覆核報告**：成本、底價、歷史依據、例外。每一頁都標示「僅供內部試算，需人工核准」。
- **客戶報價草稿**：只用第 2 節的允許欄位，與內部報告分開產生、分開下載。
- 任何輸入變動都會讓舊結果失效。

## 7. 設計審查（四個視角）

### 7.1 台灣少量多樣製造商的報價主管

| # | 質疑 | 決定 | 理由與界線 |
|---|---|---|---|
| 1 | 安全底價直接帶進客戶草稿，可以省時間 | **駁回** | 會讓底價被誤當成核准售價。草稿模組不接受任何內部物件，價格只能人工填寫 |
| 2 | 10 件和 500 件用同一個單件變動成本不合理，小量的材料比較貴 | **採納（限制）** | 沒有分量級的成本資料就不猜測；規格與報告都寫明「不模擬議價、良率、工時變化」 |
| 3 | 低於 MOQ 的數量還是想看底價 | **駁回** | 低於 MOQ 不提供底價，避免被拿去報價；如需例外，由人另外處理 |
| 4 | 版本比較應自動判斷「改價原因」 | **駁回** | 系統只顯示人工輸入的原因，不推測 |

### 7.2 成本會計／ERP 顧問

| # | 質疑 | 決定 | 理由與界線 |
|---|---|---|---|
| 1 | ProductCost 的製費可能已含開機與換線的分攤，再加批次費會重複 | **採納** | 模式 A 一律不加批次費；模式 B 不使用 ProductCost；兩種模式互斥 |
| 2 | 空白的委外費常被當成 0 | **採納** | 模式 B 所有成本欄位都必填，空白一律阻擋；0 必須明確填寫 |
| 3 | 成本基準日與試算日不一致 | **採納** | 基準日晚於試算日 → 阻擋；早於 365 天以上 → 警告 |
| 4 | 自動從完整成本拆出材料、人工比例 | **駁回** | 無依據，不做 |

### 7.3 資安與客戶資料保護

| # | 質疑 | 決定 | 理由與界線 |
|---|---|---|---|
| 1 | 從內部報告刪欄位產生草稿，容易漏刪 | **採納** | 改用允許欄位清單，從頭組成；測試會掃描每一格 |
| 2 | 隱藏工作表、定義名稱、文件屬性可能藏資料 | **採納** | 草稿只有一張可見工作表，沒有定義名稱；測試會檢查 |
| 3 | 草稿被當成已核准的正式報價 | **採納** | 草稿第一列固定標示狀態；系統不產生簽名或核准紀錄 |
| 4 | 草稿可以同時包含多位客戶 | **駁回** | 一份草稿只有一位客戶 |

### 7.4 客戶導入與售後服務

| # | 質疑 | 決定 | 理由與界線 |
|---|---|---|---|
| 1 | 客戶的批次成本放在各種 Excel 裡 | **採納** | `BatchCost` 加入既有欄位對應機制 |
| 2 | 客戶沒有明細成本怎麼辦 | **採納** | 可以用模式 A，但報告會寫明「未計入批次固定費」 |
| 3 | 草稿需要公司抬頭、Logo、條款範本 | **延期** | 先提供純文字欄位；版面客製依真實客戶需求再決定 |
| 4 | 想要直接把草稿寄給客戶 | **駁回** | 不做自動寄送 |

### 7.5 未解決的阻擋級疑義

沒有。既有規格與新功能沒有無法安全解決的矛盾：既有成本定義不變，新模組只讀取既有結果。
